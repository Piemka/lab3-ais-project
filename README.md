Тема: Автоматизация управления проектом по разработке и внедрению автоматизированной информационной системы.

1. Цель работы
Получение первоначальных навыков использования Issue Tracking System (системы отслеживания задач) для управления проектами по разработке и внедрению АИС. Формирование плана работ, имитация выполнения задач, мониторинг и формирование отчета.

2. Выбор инструмента
В качестве Issue Tracking System была выбрана платформа GitHub (разделы Issues и Projects).
GitHub предоставляет полный спектр необходимых инструментов: задачи (Issues), канбан-доски (Projects), этапы (Milestones), систему меток (Labels) и возможность ведения комментариев для учета времени. Это прямой аналог TrackStudio, рекомендованного в методичке.

3. Пошаговое выполнение работы
Шаг 1. Создание репозитория и настройка рабочего пространства
Был создан публичный репозиторий lab3-ais-project. Для визуализации плана был создан проект (Project) с типом отображения «Канбан-доска» (Board) и базовыми колонками: Todo (Сделать), In Progress (В работе), Done (Готово).
Шаг 2. Создание справочников (Labels и Milestones)
В соответствии с этапами WBS из Лабораторной работы № 1 были созданы:
•	Milestones (Вехи/Этапы): «Фаза 1. Анализ», «Фаза 2. Проектирование», «Фаза 3. Реализация», «Фаза 4. Тестирование», «Фаза 5. Внедрение».
•	Labels (Метки): Для разделения типов работ и ролей созданы метки задача, веха, Фаза 1...Фаза 5, а также метки ролей (например, Роль "аналитик", Роль "разработчик").
•	Custom Fields (Пользовательские поля): В настройках проекта были созданы поля для хранения плановых данных: WBS код, Фаза, Исполнитель, Длительность, дн, Старт, день, Финиш, день, Затрачено часов. Эти поля необходимы для формирования сводных таблиц и отчетов.
Шаг 3. Формирование плана задач (Issues)
В разделе Issues были созданы 20 задач в соответствии с календарным планом (WBS) из ЛР №1.
Для каждой задачи:
1.	В заголовке указан код и название (например, «WBS 1.1 Анализ предметной области и объекта»).
2.	В описание внесены плановые параметры (длительность, даты, предшественники, тип связи).
3.	Назначены соответствующие метки (Labels) и выбран этап (Milestone).
4.	Задачи добавлены на Канбан-доску в колонку Todo.
Шаг 4. Имитация выполнения работ и учет времени
В соответствии с методическими указаниями (раздел «Сообщения»), учет времени и смена статусов выполнялись путем добавления комментариев (сообщений) к задачам.
•	Задачи, переведенные в статус «В работе» (In Progress): При взятии задачи в работу к ней добавлялся комментарий о начале работ с указанием потраченного времени (например: «Приступил к выполнению. Провожу анализ. Затрачено: 16 часов»).
•	Завершенные задачи (Done): При завершении работ задача перетаскивалась в колонку Done, закрывалась (Closed), а в комментарии фиксировалось итоговое время (например: «Задача выполнена. Итого затрачено: 40 часов»). Также итоговая цифра дублировалась в числовое поле Затрачено часов.
•	Текущий статус проекта: Фазы 1 и 2 полностью завершены (задачи закрыты). Задачи Фазы 3 переведены в статус In Progress (в поле затрачено часов внесено промежуточное время). Задачи Фаз 4 и 5 остаются в Todo.
Шаг 5. Мониторинг и создание отчетов
Для контроля хода выполнения проекта были настроены различные представления (Views) и сформированы отчеты:
1.	Канбан-доска: Показывает текущее распределение задач по статусам.
2.	Табличное представление: Позволяет увидеть все плановые и фактические показатели в виде сводной таблицы.
3.	Группировка по фазам: Показывает прогресс внутри каждого этапа.
4.	Отчет по вехам (Milestones): GitHub автоматически рассчитывает процент закрытых задач для каждой вехи.
